## 1. 实现结果

新增 `RedisRPMLimiter` 和 go-redis v9 基础设施适配。每次请求把 Platform、Tenant、Project、VirtualKey 四个 Effective RPM hard 放入同一 Lua；脚本先检查全部字段，全部允许才统一递增，任一拒绝无部分计数。允许结果返回四层计数和 soft 是否超限，拒绝结果返回 canonical 首个 Scope、当前值、hard、ResetAt 和 RetryAfter。

## 2. 时钟、Key 与 TTL

分钟窗口以 Redis `TIME` 为最终权威。本地预测只用于正常路径一次往返；窗口不一致时 Lua 在读写前返回服务器窗口，Go 最多重试 3 次。窗口 Key 使用版本化 `{rpm}` hash tag，同一分钟四层字段位于一个 Hash。每次成功脚本用 `PEXPIREAT(next minute + retention)` 设置服务器绝对过期，默认 retention 5 秒，不按请求滑动续期。

已有计数必须是十进制非负精确整数；字符串、负数、越界、非法 RESP 或 Policy 回显不一致都 fail closed。Redis 连接错误不会被伪装为业务 429，也不会静默绕过全局 hard。
