# 项目文档

文档与代码同等维护。任何改变接口、事件、数据库、失败语义、安全边界或部署方式的修改，都必须同步更新对应文档。

## 目录

- `product/`：产品范围、用户故事、验收标准和非目标。
- `architecture/`：系统上下文、组件、数据模型、SLO 和技术选型。
- `adr/`：架构决策记录；已接受的决策不可直接改写历史，只能由新 ADR 取代。
- `api/`：OpenAPI、SSE、错误码和事件 Schema。
- `security/`：威胁模型、权限矩阵、密钥与数据留存策略。
- `development/`：完成标准、版本策略、开发和测试约定。
- `runbook/`：运维故障处理步骤。
- `reports/`：验收、性能、安全、故障和对账报告。

## 命名规则

- ADR：`NNNN-short-title.md`，编号递增。
- 报告：`YYYY-MM-DD-topic.md` 或阶段固定名称。
- 架构图优先使用 Mermaid，并在正文解释关键边界。
- 文档中的指标必须注明环境、版本、数据量和测量方式。
