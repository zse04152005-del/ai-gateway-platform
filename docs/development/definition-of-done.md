# Definition of Done

一个开发任务只有同时满足适用条目时才能标记 `[x]`。

## 1. 行为与范围

- 实现与任务验收条件一致，没有未经记录的范围扩张。
- 错误、超时、取消、重试和部分失败行为已明确。
- 多租户、权限和敏感数据边界已检查。

## 2. 代码质量

- 代码已格式化，通过静态检查。
- 公共接口、复杂状态和非显然权衡有必要注释。
- 不存在明文密钥、无界队列、无限重试和静默吞错。
- 新依赖有明确用途、许可证和安全评估。

## 3. 测试

- 正常、边界、失败和并发路径有自动化测试。
- 修复缺陷时先增加能复现问题的回归测试。
- Provider Adapter 变化通过一致性测试。
- 涉及性能的改动有同环境前后对比。

## 4. 数据与兼容性

- 数据库迁移可重复、向后兼容并有回滚/前滚说明。
- 异步消费者幂等，事件有版本。
- API 变化更新 OpenAPI、错误码和兼容性说明。
- 配置与价格变化采用版本，不覆盖历史事实。

## 5. 安全与隐私

- 身份、权限、租户和审计已覆盖。
- 日志、Trace、Metric Label 和错误没有 Prompt、Response、Key 或个人数据。
- 外部地址、Header、正文大小和流 Chunk 具有验证与限制。
- 高风险威胁有测试或明确延期记录。

## 6. 可观测性与运维

- 新关键路径有必要指标、Trace 和结构化日志。
- 指标 Label 基数受控。
- 新故障模式有告警或 Runbook。
- 资源泄漏、积压和重试放大可观察。

## 7. 文档与证据

- README、架构、ADR、API 或 Runbook 已按影响更新。
- 执行清单填写完成日期和测试/报告/提交证据。
- 性能数字包含环境、版本、数据规模、并发和持续时间。

## 8. 不得标记完成的情况

- 只能在开发者本机偶然运行，无法复现。
- 测试失败、被跳过或依赖真实未授权密钥。
- 关键 TODO 没有进入清单或 Issue。
- 只完成代码但没有迁移、配置、文档或验证。
