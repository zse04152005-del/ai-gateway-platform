# 服务等级目标与指标

> 状态：Proposed for MVP  
> 日期：2026-07-30  
> 对应任务：P01-T04

SLO 只衡量网关可控制的行为，外部 Provider 的生成耗时与可用性单独展示，不混入网关自身 SLO。

## 1. SLI 与目标

| SLI | 计算方式 | MVP 目标 | 窗口 |
|---|---|---:|---|
| 数据面可用性 | 非网关内部 5xx 的合格请求 / 合格请求 | 99.9% | 30 天演示口径 |
| 非流式附加延迟 | 网关端到端减去测得的 Provider 时间 | P95 < 30ms | 5 分钟/发布测试 |
| SSE 首 Token 附加延迟 | 客户端首事件时间减去上游首事件时间 | P95 < 50ms | 5 分钟/发布测试 |
| 取消传播 | 客户端断开到上游 Context 完成 | P95 < 1s | 发布测试 |
| 配置同步 | 发布提交到 Gateway 激活新版本 | P95 < 5s | 连续测量 |
| 计量完整率 | 有最终计量状态的 Attempt / 总 Attempt | ≥ 99.99% | 每日 |
| 重复计费率 | 重复有效 Ledger 分录 / 总分录 | 0 | 每日 |
| 硬预算超卖 | 实际结算超过硬上限且非已批准调整 | 0 | 每日/并发测试 |

目标需要在 P13/P18 使用真实环境复核；若硬件无法达到延迟目标，记录测量结果和瓶颈，不修改或伪造数据。

## 2. 合格请求与排除

合格请求：

- 通过基本 HTTP 和认证格式校验。
- 请求在服务支持的协议和大小范围内。

不计入数据面可用性错误预算：

- 虚拟 Key 无效、过期或无权限。
- 用户超过限流/预算。
- 客户端主动取消。
- Provider 明确返回 4xx/5xx（单独计 Provider SLI）。
- 客户端提交不支持参数。

网关错误映射、计量缺失、资源泄漏和配置解析失败仍计入网关质量指标。

## 3. Provider SLI

- 请求成功率、429、5xx、连接失败和超时率。
- 首 Token 与总生成延迟。
- 每模型/部署的输入、输出、缓存与推理 Token。
- 每次成功、失败和取消的估算/实际费用。
- 熔断状态、回退次数和重试放大倍数。

## 4. 错误预算

- 数据面月度 99.9% 对应约 43.2 分钟不可用预算，仅作为设计口径。
- 如果在演示周期内消耗超过 50%，暂停非可靠性功能开发，优先修复。
- 计量重复、硬预算超卖和跨租户泄漏属于零容忍事件，不用普通错误预算抵扣。

## 5. 测量要求

- 同时采集客户端时间、Gateway Span 与 Provider Span，避免把模型生成时间算入网关附加延迟。
- SSE 记录请求开始、上游首字节、客户端首字节、最后 Chunk、客户端取消和上游结束。
- 指标不得用 requestId/userId 作为 Label；明细进入受控日志或 Trace。
- 每次性能报告记录 CPU、内存、系统、网络、Go 版本、依赖版本、并发、请求大小和持续时间。

## 6. 告警建议

- 网关内部 5xx 的短窗口与长窗口错误预算燃烧。
- TTFT 附加延迟持续超标。
- 客户端取消后上游仍运行过久。
- Attempt 计量状态长期不完整。
- 重复 Ledger、预算超卖或预留长期未释放。
- Gateway 配置版本落后或校验和不一致。
