# 0002 使用 Go 与三进程模块化架构

- 状态：Accepted
- 日期：2026-07-30
- 决策者：项目维护者

## 背景

数据面需要精确控制 SSE、连接、超时、取消与资源释放。如果一开始拆成大量微服务，会增加网络、部署和一致性复杂度，却没有真实扩容证据。

## 决策

使用 Go 1.26 系列，本机固定 1.26.5。MVP 同仓库构建 `gateway`、`control-plane`、`metering-worker` 三个进程，内部按领域模块隔离。

## 替代方案

- Java/Spring：企业生态成熟，但本项目更希望直接展示流式和连接控制。
- Python/FastAPI：适配生态丰富，但高并发长连接和类型契约不是本项目首选。
- 早期微服务：边界表面清晰，但部署和分布式事务成本过早。

## 正面后果

- 连接与取消语义可见。
- 单仓库降低 MVP 交付成本。
- 进程仍可独立部署和扩容。

## 负面后果与风险

- 需要自行约束模块依赖，避免形成大泥球。
- Docker 当前未安装，P02 需要先获得安装授权并验证版本；Go 已完成官方安装包哈希校验和真实版本检查。

## 验证方式

P03 三进程可独立启动；P07 取消/泄漏测试；P13 MVP 验收。
