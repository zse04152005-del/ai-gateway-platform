# 0005 仅在首个模型 Token 前透明故障切换

- 状态：Accepted
- 日期：2026-07-30

## 背景

流式输出开始后切换模型会把两个不同模型的内容拼接在一起，破坏语义、工具调用和计量。部分供应商错误可能在 HTTP 200 后才出现。

## 决策

只有在第一个客户端可见模型内容/推理/工具 Delta 之前，且错误可重试、总时间/Attempt/预算允许时，才可透明选择备用 Deployment。HTTP Header 和 Gateway heartbeat 不视为模型首包。

首包后失败标记 Request/Attempt 为 `PARTIAL_FAILED`，保留已知 Usage，并结束流；不拼接备用模型。

## 替代方案

- 任意时刻继续备用模型：用户体验表面连续，但内容、工具和费用不可相信。
- 完全不重试：最简单，但首包前临时故障可用性较差。

## 后果

- 语义与账单边界清晰。
- 客户端需要处理部分失败。
- 必须准确区分 heartbeat、响应头和模型首事件。

## 验证方式

P07 首包前/后故障 Fixture 与 P08 多 Attempt 路由测试。
