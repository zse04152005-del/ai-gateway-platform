# 0003 PostgreSQL 事实源与版本化配置快照

- 状态：Accepted
- 日期：2026-07-30

## 背景

数据面需要低延迟读取配置，同时控制面短时不可用不应阻断已有流量。直接在热路径查控制面数据库会引入延迟和故障耦合。

## 决策

PostgreSQL 是配置事实源。控制面把校验通过的模型、部署、价格、路由和策略构建为不可变 Snapshot，包含版本和校验和。数据面使用最近有效 Snapshot，并通过通知加周期检查更新。

## 替代方案

- Redis 作为最终事实：热读取快，但审计、事务和恢复不够清晰。
- 每请求查 PostgreSQL：一致但增加热路径延迟和故障面。

## 后果

- 控制面故障时数据面可继续服务。
- 配置存在短暂最终一致，需要版本落后告警。
- Snapshot 必须排除不必要的敏感信息。

## 验证方式

P11 发布、丢通知恢复、控制面停止和配置回滚测试。

## 当前实现

P03-T04 已实现 `internal/config.Snapshot` 与 `SnapshotStore` 基础契约：规范 JSON、SHA-256、敏感字段阻断、不可变复制、单调/幂等发布、原子读取和可取消版本等待。P11 在此契约上接入 PostgreSQL 事实源与通知/周期恢复，不改变数据面读取接口。
